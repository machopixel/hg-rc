# Brief: convert HGSIM.DLL leaf functions to C and verify them

Project: port of Heavy Gear (1997, 32-bit, VC++5, plain C) to modern Windows. Game logic must stay IDENTICAL; we replace the original compiled code one function at a time with C that behaves exactly the same. The owner (Diego) rejects guesswork: every conversion must be proven equal to the original by the checker, and names/comments must come from evidence in the code.

## What to produce for your area `AREA`
- `src/sim/AREA/AREA.h` (declarations, a short header comment saying what the area is) and one or more `src/sim/AREA/*.c` grouped by what the functions do (not one huge file; name files after the purpose). Each function gets `// FUNCTION: HGSIM 0x100xxxxx` directly above it.
- Plain C17, `#include "../simmem.h"` for access to the DLL's data: `SIM_PTR(type, 0x1xxxxxxx)` with the address the data has at the preferred base. Do NOT use libc beyond what tools/verify/rt.c provides (memset, memcpy, memmove, memcmp, strlen, strcmp, _stricmp). Keep every function's calling convention cdecl (`__cdecl`, defined away on non-Windows by simmem.h); declare them with that.
- `tools/verify/spec_AREA.py` with SOURCES and SPECS (see spec_core.py and tools/verify/README.md). Generators must set up the data the function reads (tables, structs, globals in the DLL's data via `ctx.m.uc.mem_write`, and argument buffers via `ctx.buf`) so the function actually does its work on most trials: a spec where most trials end in "both-fault" proves nothing. Run: `python tools/verify/difftest.py C:\Coding\HeavyGear\Project\HGSIM.DLL tools/verify/spec_AREA.py` from WORK. Use at least 300 trials per function; more for functions with many branches. Every function must show 0 mismatches and a low both-fault count (a trial where both versions fault is skipped). If a function needs special setup (e.g. valid pointers inside structures), write that setup.
- `src/hooks/conv_AREA.inc`: hook entries produced with `python tools/verify/hookgen.py C:\Coding\HeavyGear\Project\HGSIM.DLL Name=0xADDR ...` (one CONV line per converted function; the name must equal the C function name).

## Rules for each function
1. Read the disassembly (authoritative) and the Ghidra text (an aid; it is often wrong about types, signedness, shifts and calling convention).
2. The original must be cdecl: plain `ret` at the end and arguments on the stack. If it takes arguments in registers, ends with `ret N`, uses x87 (f* instructions), touches segment registers, calls anything, uses the Windows APIs, or uses hand-written tricks that C cannot express, DO NOT convert it; list it as skipped with the reason.
3. Match the original's behaviour exactly, including what it leaves in memory, the full 32-bit return value (eax) when the caller can see it, quirks like a 16-bit result with garbage in the top half, signed vs unsigned compares, shifts of negative numbers, and integer overflow (use unsigned arithmetic where the original wraps). If the checker finds a difference, fix the C, never loosen the test.
4. Names: if the code makes the purpose clear, use a short descriptive name in `Area_VerbNoun` style (like Cache_FindName, Timer_Reset); otherwise `Sim_<hex address>`. Do not invent a meaning you cannot show. Comments only for things a reader cannot see from the code (struct field meanings that you proved, why a quirk is kept). Struct fields are accessed as offsets in the style of src/sim/mem/syscache.c unless you define a small struct with offsets you verified.
5. Quality over count. Do not pad. A skipped or dropped function with a clear reason is a good result; a function whose test setup is weak is not.
